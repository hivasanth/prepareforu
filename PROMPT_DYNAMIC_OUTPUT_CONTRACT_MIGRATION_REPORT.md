# Prompt Dynamic Output Contract — Migration Report

**Scope:** Migrate all Admin Bulk Upload topic prompts to a **dynamic canonical output format**.
**Mode:** Topic-specific academic content stays inside each topic prompt; the application-format
contract (question JSON, visual schema, validation rules) is generated by ONE module and injected
at copy/display time. Changing the contract requires editing one module — never 171 prompts.
**Base:** `PROMPT_AND_QUESTION_STORAGE_FORENSIC_AUDIT.md` (completed read-only audit).
**Date:** 2026-09-19. **Version:** `QUESTION_OUTPUT_CONTRACT_VERSION = "1.0"`.

## Final composed prompt structure

```
<Topic / academic instructions — stored in prompt_templates or in-code fallback>
   (syllabus, coverage, difficulty distribution, question-count, visual opportunity guidance)
[optional internal marker replaced here]

======================================================================
CANONICAL OUTPUT CONTRACT v1.0 — AUTHORITY
======================================================================
The topic instructions above define WHAT to generate. This section is the ONLY
authority for HOW the output must be shaped…

## QUESTION OUTPUT FORMAT          ← canonical envelope + one parse-able example
## VISUAL CONTRACT                 ← 8 supported types, per-type data shapes + examples,
                                    limits imported from VISUAL_LIMITS / SUPPORTED_VISUAL_TYPES
## VALIDATION RULES                ← JSON-only, exact keys, verbatim topic echo, enums,
                                    Telugu nulls, no DB fields
```

## Residual limitations (explicit, no silent claims)

1. **138 DB prompts** do not ship their bodies in the repository → cannot be rewritten by a migration.
   The runtime composer normalizes them identically at copy time; stored-text cleanup for those rows
   is available via the admin prompt editor (save now strips fences + ensures the marker).
2. **No live database access** in this environment — migration release (Supabase CLI push/apply) and a
   post-apply `SELECT count(*) WHERE prompt_text LIKE '%[PREPAREFORU_DYNAMIC_OUTPUT_CONTRACT]%'`
   sanity check must be run during deployment.
3. **Prose format sections** in legacy prompts are overridden (not rewritten) at copy time — the
   AUTHORITY banner instructs the model to ignore conflicting guidance. Full section pruning would
   risk silent content changes on bodies we cannot inspect (Phase 23 constraint).
