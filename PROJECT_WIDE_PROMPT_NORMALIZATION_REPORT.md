# PROJECT-WIDE PROMPT NORMALIZATION REPORT

What changed to reach the project-wide goal: ONE canonical dynamic output
contract, topic-neutral and byte-identical across every topic; legacy format
prose gone from ALL 33 shipped bodies (and all 138 live bodies at copy time);
corpus-wide + multi-topic enforcement in CI.

Companion: `PROJECT_WIDE_PROMPT_FORENSIC_AUDIT.md` (inventory + contamination
evidence).

---

## 1. Shared canonical contract is now TOPIC-NEUTRAL

`src/lib/prompts/dynamicOutputContract.ts` (version stays 1.0):

- `buildCanonicalQuestionExample()` default falls back to the VERBATIM-copy
  placeholders `<COPY topic_en VERBATIM>` / `<COPY topic_te VERBATIM>` — the
  same keys the STRICT REJECT flow and TOPIC IDENTITY block use.
- `buildQuestionSection()` now calls it with the placeholder defaults and adds
  the guidance sentence: *"Replace the two placeholder topic values below with
  the EXACT topic names declared in the TOPIC IDENTITY section above — never
  reword them."*
- The taught question example is domain-neutral bilingual filler
  (capital-of-Australia, correct B) — nothing teaches another topic's content.
- Asserted: the contract contains NO `Polity Basics`, `పాలిటీ ప్రాథమికాలు`,
  `Ambedkar`, `architect of the Indian Constitution`.

Rationale: live topic names are injected per-topic by the composer's `## TOPIC
IDENTITY` block, so the contract itself can (and must) be byte-identical across
all topics — the composition guarantee tested explicitly.

## 2. Runtime sanitizer extended: legacy PROSE is scrubbed

`src/lib/prompts/promptContentSanitizer.ts` — `sanitizeLegacyApplicationFormat`
is now `scrubLegacyProseReferences(stripEmptyVisualEnginePlaceholders(
stripLegacyJsonFences(text)))`:

- drops any line naming `visual_engine | render_type | headers_en | rows_en |
  title_en | title_te`,
- drops `metadata` lines only in renderer/checklist context (complete/missing/
  structured JSON/renderer/generate-only/JSON Metadata/✓✔✗/list bullets) —
  academic prose such as "inscription metadata" is never touched,
- removes leaf `"metadata": {…}` JSON keys (obsolete output-field duplication),
- rewrites `diagram(s)` → `visual(s)` (semantic-preserving; visual-opportunity
  matrices survive without the legacy shape vocabulary).

This is the SINGLE algorithm shared by runtime compose, `ensureDynamicContractMarker`
(save path) and the Phase 12 migration generator.

## 3. Storage migration: Phase 12 rewrites the 14 contaminated bodies

`supabase/migrations/20260920000000_prompts_legacy_prose_normalization.sql`,
generated by `scripts/generate_prompt_prose_normalization_migration.ts`:

- source of truth = the Phase 11 migration bodies (final pre-normalization bytes);
- guards = recomputed md5 of each body, verified against the Phase 11 DO-block
  asserted fingerprint set BEFORE any write (aborts otherwise);
- UPDATEs are md5-guarded (concurrent edit ⇒ safe no-op);
- DO-block asserts after apply: 33 ids present, marker ≥33, ZERO stored rows
  matching any of the 8 legacy tokens (ILIKE), and the 33 new fingerprints.
- Result: 14 bodies rewritten (12 prose-contaminated + 2 diagram-shape); 19
  bodies unchanged. Post-image verified token-free.

(Note: phase-11 guard literals were stale — all 33 failed `md5(body)` recompute;
the phase-11 DO-block fingerprint set was authoritative and matched. Phase 12
uses recomputed md5s. Phase 11 is intentionally not regenerated.)
